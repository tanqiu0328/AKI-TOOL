# 将自定义烧录建模为独立烧录方案

AKI-TOOL 现有固件烧录由 ESP-IDF 构建产物中的 `flash_args` 驱动，无法表达 `fctry.bin` 等独立二进制镜像的固定地址烧录。决定在现有“ESP 烧录”工具内增加独立的“自定义烧录”模式，用可复用的“自定义烧录方案”描述多个自定义烧录项，并与固件烧录共用设备连接设置。两种烧录操作保持独立，避免日常固件烧录隐式覆盖设备级数据，也避免把通用烧录能力继续绑定到某个工程的构建产物

## 考虑过的方案

- 将自定义镜像自动附加到现有固件烧录：操作更少，但会让设备凭据等数据在日常开发烧录中被反复覆盖
- 仅提供单 BIN 快速烧录：实现简单，但无法复用多分区、多镜像工作流
- 创建新的侧栏工具：边界直观，但会重复芯片、串口、波特率、下载模式和日志能力

## 后果

- 一个自定义烧录方案可以包含多个自定义烧录项，每项具有名称、十六进制绝对地址、默认启用状态和文件来源
- 文件来源支持固定文件和每次选择；固定文件只保存绝对路径，不复制 BIN 内容
- 方案支持本机创建、显式保存、另存为、切换和删除，不进入工程仓库，也不在首版提供导入、导出或同步
- 执行时可以临时取消烧录项或替换“每次选择”的文件，且不会隐式修改已保存方案
- 每次执行前必须确认芯片、串口、方案以及各文件的大小和地址范围
- 文件缺失、未选择任何烧录项、地址无效、地址未按 4 KiB 对齐、地址范围重叠或超出设备实际 Flash 容量时禁止写入
- 所有启用项预检通过后，通过一次 `esptool write_flash` 命令提交，并使用 `esptool` 默认写入校验
- 自定义烧录不触发编译或自动串口监视，也不在首版开放高级 `esptool` 参数或内置 RainMaker 地址
